

# Auto-Voucher Generation & Remove Manual Claim

## Problem
When a patron hits the stamp threshold, the system currently expects them to manually tap "Claim." The user wants stamps to automatically generate a voucher when the threshold is reached, reset the card to 0, and let new stamps accumulate immediately. Vouchers pile up on the Vouchers tab.

## What's Already Working
The DB trigger (`credit_loyalty_on_order`) already has auto-redemption logic that generates a discount code and resets stamps to 0 when `stamps_count >= stamp_threshold`. This was added in the last migration.

## What's Broken / Missing

### 1. Missing `expires_at` on auto-generated vouchers
The trigger inserts into `discount_codes` without setting `expires_at`, so vouchers have no expiry date. The trigger needs to calculate expiry from `loyalty_rewards.voucher_validity_days`.

**Fix**: Update `credit_loyalty_on_order` and `credit_loyalty_on_waitlist` trigger functions to read `voucher_validity_days` from the reward and set `expires_at` on insert.

### 2. Frontend still shows manual "Claim" button
The `can_claim` logic and `handleClaim` function are now unnecessary since vouchers are auto-generated by the trigger.

**Fix in `LoyaltyReadyFlow.tsx`**:
- Remove `can_claim` from `VenueStampData` interface and data fetching
- Remove the "Claim" button UI block (lines 370-391)
- Remove `handleClaim` function and `claiming` state
- Remove the gift badge on hub logos (the ticket badge already shows voucher count)
- Keep the "ready to claim" text but change it to something like "Voucher earned! Check your vouchers tab"

### 3. Edge function `claim-loyalty-reward` is now redundant
Since auto-redemption happens in the trigger, the manual claim endpoint is no longer needed. However, keeping it doesn't hurt — we just won't call it from the frontend anymore.
